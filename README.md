# بُعد — Bu'd

الموقع التعريفي لـ بُعد: تطوير تطبيقات الجوال والويب والأنظمة البرمجية، وإنتاج أفلام تسويقية بالذكاء الاصطناعي.

موقع ثابت بخمس صفحات، بدون اعتمادية بناء غير Node و Chrome الموجودَين أصلاً على الجهاز. العربية هي الأساس والإنجليزية خيار.

## البنية

| المسار | الوظيفة |
|---|---|
| `src/index.html` | **المصدر الوحيد**: كل الصفحات والتنسيقات والسكربت |
| `src/og.html` | تصميم بطاقة معاينة الرابط |
| `tools/build.js` | يقسّم المصدر إلى خمس صفحات حقيقية + `robots.txt` + `sitemap.xml` |
| `tools/prerender.js` | يطبخ كل صفحة في Chrome فتخرج عربية جاهزة للفهرسة |
| `tools/make-og.sh` | يحوّل `src/og.html` إلى `og.png` بمقاس ١٢٠٠×٦٣٠ |
| `index.html` وأخواتها | الناتج المنشور — لا تعدّلها يدوياً |

الصفحات الخمس: `/` و `/apps/` و `/film/` و `/catalog/` و `/brief/`.

## التعديل

عدّل داخل `src/` فقط، ثم أعد البناء:

```bash
node tools/build.js && node tools/prerender.js
```

أي تعديل مباشر على `index.html` في الجذر أو في مجلدات الصفحات يُمسح عند البناء التالي.

لتعديل بطاقة المعاينة:

```bash
bash tools/make-og.sh
```

## لماذا خطوة الطبخ المسبق

النص العربي يعيش في سمات `data-ar` ويحقنه السكربت عند التحميل، والكتالوج كله يُبنى برمجياً.
يعني أن البايتات المُرسَلة كانت إنجليزية وخالية من الكتالوج — وهي ما يفهرسه محرك البحث.
`prerender.js` يحمّل كل صفحة في Chrome بلا واجهة ويحفظ الـ DOM الناتج، فتصل العربية
والكتالوج إلى الزاحف من أول بايت. السكربتات تبقى في الناتج وتعيد تطبيق الحالة نفسها،
فالسلوك لا يتغيّر ومبدّل اللغة يظل يعمل.

## النشر

مربوط بـ Vercel. كل دفعة إلى `main` تنشر تلقائياً على https://bud-co.com

## بعد النشر — خطوات لا يغني عنها الكود

1. أضف الموقع في [Google Search Console](https://search.google.com/search-console) وأرسل `sitemap.xml`.
2. أنشئ [Google Business Profile](https://business.google.com) باسم ونشاط وعنوان تبوك — أقوى عامل منفرد للظهور في النتائج المحلية.
3. اجمع تقييمات حقيقية على الملف التجاري.
4. اطلب روابط من مواقع سعودية حقيقية: الغرفة التجارية، أدلة الأعمال، عملاء يذكرونك.
